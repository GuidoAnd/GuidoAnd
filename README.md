## 🔐 Infrastructure & Agent Isolation

I also experiment with running development agents inside **restricted container environments** rather than giving them unrestricted access to the host.

Some of the controls I work with include:

- Non-root containers
- Read-only filesystems
- Dropped Linux capabilities
- Resource limits
- Dedicated Docker networks
- No Docker socket access
- Scoped repository permissions
- Short-lived credentials
- GitHub App authentication

```text
Host
 │
 └── Docker
      │
      └── Agent Sandbox
           ├── Restricted user
           ├── Limited filesystem
           ├── Controlled network
           ├── Repository scope
           └── Temporary credentials
```

The objective is to apply **least privilege, isolation and reproducibility** to AI-assisted development workflows.

## 🧭 Engineering Approach

**Reproducibility**  
Projects should be reasonably easy to recreate from their repository and documentation.

**Least Privilege**  
Services, containers and automation should receive only the permissions they require.

**Incremental Complexity**  
Start with a small working system and introduce additional infrastructure only when it solves a real problem.

**Documentation**  
Architecture, technical decisions and operational procedures should be understandable without reverse-engineering the entire project.

**Operational Thinking**  
Deployment is only part of the lifecycle. Systems also require monitoring, logging, health checks and troubleshooting.
