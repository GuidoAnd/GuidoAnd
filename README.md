# 🔐 Secure Development & Agent Isolation

One area I am actively exploring is the controlled use of AI development agents.

Instead of providing unrestricted access to development environments, I experiment with sandboxed containers and restricted permissions.

Some controls include:

- Non-root containers
- Read-only filesystem where possible
- Dropped Linux capabilities
- No privileged mode
- No Docker socket access
- Resource limits
- Dedicated Docker networks
- Temporary filesystems
- Scoped repository permissions
- Short-lived credentials
- GitHub App authentication

Example environment:

```text
Host
 │
 └── Docker
      │
      └── Agent Sandbox
           │
           ├── Restricted user
           ├── Limited filesystem
           ├── Controlled network
           ├── Repository scope
           └── Temporary credentials
```

The objective is to combine developer productivity with **least privilege, reproducibility and controlled access**.

# 📚 Engineering Principles

Across my projects I try to follow a few consistent principles.

### Reproducibility

A project should be reasonably easy to recreate from its repository and documentation.

### Least privilege

Services, containers and automation tools should receive only the permissions they require.

### Documentation

Architecture and technical decisions should be understandable without having to reverse-engineer the entire codebase.

### Incremental complexity

I prefer starting with a small working system and adding infrastructure components only when they solve a real problem.

### Operational thinking

Deployment is not the end of a project.

A system also needs:

- Monitoring
- Logging
- Health checks
- Troubleshooting procedures
- Recovery strategies
